\section{Experimental Setup}
\label{sec:setup}

\subsection{Status and Data Sources}

This section specifies the proposed real-cohort evaluation rather than completed clinical results. The supplied implementation supports data ingestion, two reference score learners, synthetic diagnostics, and cached-score budget evaluation. External backbone adapters, the full comparative grid, and clinical effectiveness experiments remain incomplete. Consequently, no real-cohort performance or measured accelerator-hour budget is claimed in this draft.

The public Challenge 2019 release contains 20{,}336 records in training set A and 20{,}000 in training set B, from two hospital systems.\footnote{Official data and label documentation: \url{https://physionet.org/content/challenge-2019/1.0.0/}.} A third hospital was used as hidden challenge evaluation data and is not a public training subset for an A$\rightarrow$C experiment. The intended cross-hospital comparison therefore uses A$\rightarrow$B, with the reverse direction as an optional replication. Record identifiers provide record-disjoint partitions but cannot establish whether repeated admissions belong to the same individual, leaving independent patient sampling as an assumption requiring separate justification.

Challenge 2012 supplies an in-hospital mortality task using measurements from the first 48 hours of an intensive-care stay.\footnote{Official format, variable units and separate outcome files: \url{https://physionet.org/content/challenge-2012/1.0.0/}.} Its patient files are long-form observations, and mortality outcomes are joined from separate files by RecordID. Measurements are assigned to the next hourly decision at which they are available, with the last valid measurement retained within each interval and no backward filling. The resulting 49 decision points at hours 0 through 48 are a mortality input, not a deterioration follow-up with an invented event onset; cross-task transfer also requires explicit unit conversion and a shared feature schema before any pretrained model can be reused.

\subsection{Partitioning, Labels and Eligibility}

The intended source split is $60\%$ training, $15\%$ validation, $10\%$ calibration and $15\%$ test, with no record crossing partitions. Training and validation determine the scorer, preprocessing, structural parameters and threshold grid before risk calibration. Calibration determines the deployed threshold without test-set tuning, while exposure-based eligibility must be declared independently of the calibration and test samples. An outcome-dependent purge is not needed for record separation and is reserved for explicitly reported sensitivity analyses because it changes the population and may introduce selection bias.

The 2019 SepsisLabel becomes positive six hours before the clinical onset defined by the challenge, so the default reader's label-boundary time must not be called clinical onset. An explicit six-hour shift reconstructs the candidate clinical time only when the label boundary is observed within the record. Initially positive records have an uncertain, left-censored onset and are not assigned a fabricated six-hour clinical time; shifted events outside observed follow-up are also ineligible for observed lead-time evaluation. Padding and post-onset times are excluded from event-label training rather than labelled negative, while alarm-rate evaluation still counts the entire declared observed exposure.

For local target calibration, the scorer and structural policy parameters would remain fixed from the source, with disjoint target calibration and test records. The proposed target sample sizes are $m\in\{50,100,200,500\}$, but feasibility must be reported because small samples may yield only the no-alarm fallback. A source-only transferred threshold is a separate distribution-shift diagnostic and is not assigned the same-population certificate. All comparisons use shared requested budgets, and realised alarm rates are reported rather than assumed equal.

\subsection{Score Models and Comparators}

The implemented learners are a prefix-feature logistic model, optionally replaced by LightGBM, and a unidirectional masked gated recurrent network. Prefix features use only current or past observations, and future-perturbation tests check causal predictions. The recurrent reference consumes values, observation masks and finite elapsed-time features, with missing static values zero-imputed; it is not a GRU-D reimplementation and currently trains on CPU. Additional architectures are prospective extensions and must pass the same causality checks before inclusion, particularly when an imputation method ordinarily uses an entire trajectory.

Clinical-score functions in the package are research-only partial instruments, not validated reconstructions of the complete scales. In particular, the available NEWS components omit consciousness and supplemental oxygen, SIRS omits the immature-neutrophil alternative, and SOFA lacks several required components. Their raw scores are not calibrated probabilities and cannot be passed directly to probability-calibration metrics without a training-only probability adapter. Retrospective top-$k$ selection and test-rate-tuned thresholds, if added, must be labelled nondeployable oracle comparators rather than fair prospective baselines.

\subsection{Metrics and Uncertainty}

The proposed evaluation reports discrimination, calibration, patient-average alarms per day, sensitivity, and lead time among detected eligible events. A lead-time median is accompanied by the detection denominator because improving a conditional median can reflect missing harder cases rather than detecting earlier. Budget diagnostics distinguish the population expectation in \cref{eq:bound}, the held-out finite-cohort mean, and the per-patient exceedance tail. The synthetic driver repeats partitions of a reused cohort, so its Wilson intervals are descriptive and do not establish independent-binomial coverage or prove the population-risk theorem.

Patient-block bootstrap resampling is the intended uncertainty procedure for correlated hourly predictions. DeLong tests are appropriate only when their observational units satisfy the required independence assumptions, not when every correlated hour is treated as an independent patient. Paired operational comparisons should report effect sizes and exact $p$-values, with zero differences handled consistently in the signed-rank statistic and rank-biserial effect size. Repeated seeds and partitions are to be reported transparently, without declaring a method valid merely because a descriptive interval happens to contain the nominal level.

\subsection{Reproducibility and Compute}

The reference package requires Python 3.10 or later, with optional PyTorch and LightGBM dependencies. Threshold grids are fixed before risk calibration, and the deployment-support alarm bound includes both refractory and escalation settings. The conservative default in the generic budget driver allows any one-step positive exposure, while a larger independently declared minimum is an explicit eligibility restriction. Version-two score caches reject obsolete unversioned scores, so earlier noncausal model outputs must be regenerated; exact clinical training versions, partitions, runtime and device measurements remain to be recorded when those experiments are executed.
